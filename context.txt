
## Objective

Replace the current static image placeholder in the Tenaciti public website hero with a **high-fidelity, cinematic interactive product demo** that visually communicates what Tenaciti actually is:

> **Your Semester, Managed.**

The demo should make the visitor understand, without reading a feature list, that Tenaciti is an **AI personal assistant for academic life** that understands a student's connected academic workspace and can actively operate it.

The demo must feel like a real Tenaciti product experience, not a generic chatbot mockup and not a prerecorded video.

---

# 1. Core implementation direction

Implement the hero visual as a **coded React UI animation**, not a video.

Use:

* React components
* CSS transitions/animations
* JavaScript/React state for scene sequencing
* Existing Tenaciti UI components/styles wherever practical
* Existing icons and visual language
* Existing feature UI/screens where they can be reused
* Dummy/local data specifically for this marketing demo

Do **not** make real backend/API/LLM calls.

This is a deterministic product simulation designed to visually demonstrate the product.

The demo should automatically play through several scenarios and loop smoothly.

It should also be architected cleanly enough that individual scenes, timings, copy, and dummy data can easily be changed later.

---

# 2. Do not create a generic chatbot

The AI assistant feature/page is not implemented yet.

For this hero demo, create a **purpose-built visual representation of Tenaciti's AI assistant**.

Do not wait for the actual chatbot implementation.

The AI should visually feel like the central intelligence of the product.

Use a creative representation such as:

* a central Tenaciti AI entity/avatar
* a minimal AI core/orb
* a stylized assistant node
* an intelligent central workspace element

From this central AI element, visually show **hands/arms, connection lines, or tool-call branches** reaching toward different academic tools.

For example:

```text
                    Notes
                      ↑
                      │
Documents ←      TENACITI AI      → Topics
                      │
                      ↓
                   Goals
                      │
                      ↓
                Assessments
```

Do not make this look like a technical developer diagram.

It should look polished and product-oriented.

The visual metaphor should communicate:

> One AI assistant operating many connected parts of a student's academic life.

---

# 3. Hero scenes

Implement approximately **6 major scenarios**.

Do not cram all six onto the screen simultaneously.

Each scene should have a clear beginning, action, transformation, and result.

The overall sequence should feel like one continuous product experience.

---

This should be the strongest visual scene.

Start with the document-upload experience.

Example dummy document:




# 11. Seamless transitions are mandatory

This is one of the most important requirements.

Avoid:

```text
Screen disappears
↓
Next screen suddenly appears
```

Instead use transitions that imply continuity.

Examples:

### Document → processing

Document card remains in place while its state changes:

```text
Uploaded
↓
Processing
↓
Processed
```

### Extraction button → roadmap

The clicked button should:

```text
press
↓
loading state
↓
processing state
↓
content expands/transforms
↓
roadmap appears
```

### Topics → confidence

The selected topic should remain visually anchored while the confidence UI emerges from it.

### AI → tool call

The AI should visibly connect to the relevant tool.

For example:

```text
AI
 │
 ├────→ Notes
 │
 └────→ Topic
```

The connection should animate rather than simply appearing.

### Tool call → result

Use:

```text
Working...
↓
✓ Complete
```

with smooth state transitions.

The demo should feel like **one continuous system changing state**.

# 15. Performance requirements

The animation must be lightweight.

Do not use:

* video
* WebGL
* canvas unless absolutely necessary
* large image assets
* external animation libraries unless already installed and justified
* real API calls
* real LLM calls

Prefer:

* CSS transitions
* CSS transforms
* opacity
* SVG
* React state
* local dummy data

Use GPU-friendly properties where possible:

```text
transform
opacity
```

Avoid repeatedly animating:

```text
width
height
top
left
```

unless necessary.

---

# 16. Accessibility

Respect:

```css
@media (prefers-reduced-motion: reduce)
```

When reduced motion is enabled:

* disable major transitions
* show stable final states
* keep all information readable
* don't make functionality dependent on animation

The demo should also not interfere with page navigation or keyboard interaction.

The entire sequence should automatically play.

Example:

```text
Scene 1
Document → Roadmap

        ↓

Scene 2
Document → Topics → Confidence

        ↓

Scene 3
AI → Note

        ↓

Scene 4
AI → Study Recommendation

        ↓

Scene 5
AI → Goal

        ↓

Scene 6
AI → Workspace Search

        ↓

Smooth reset

        ↓

```

Avoid an obvious hard reset.

The final scene should visually transition into the initial state.

For example, after the search results disappear, the document can re-enter the workspace and begin the first scene.

# 18. Do not overstuff the demo

The purpose is not to show every feature.

The six core stories are:

1. **Turn a document into a roadmap**
2. **Turn a document into trackable topics**
3. **Capture knowledge through AI**
4. **Use connected academic context to decide what to study**
5. **Turn natural language into goals/actions**
6. **Search the student's entire academic workspace**

Other features should appear naturally inside these interactions:

* Courses
* Assessments
* Notes
* Topics
* Goals
* Roadmaps
* Progress
* Confidence
* Documents
* Connected relationships
* GPA
* Study streak

---

# 19. Important product principle

The animation should repeatedly communicate this progression:

```text
Student says / uploads something
              ↓
         Tenaciti understands
              ↓
       Tenaciti connects context
              ↓
       Tenaciti takes action
              ↓
      Academic workspace changes
```

That is the central product proposition.

Do not make the demo primarily about "AI chatting."

Make it about **AI understanding and acting**.

# 22. Implementation process

Before coding:

1. Inspect the existing repository structure.
2. Find the public website/landing page implementation.
3. Find all existing components corresponding to the features above.
4. Identify reusable UI components.
5. Identify the existing design tokens/styles.
6. Identify the existing routing/layout structure.
7. Determine the cleanest location for the new hero demo component.

Then implement the demo.

Do not create unnecessary new dependencies.

Do not modify unrelated product functionality.

Do not implement the actual AI chatbot backend.

Do not implement a new production AI architecture.

This is specifically a **public website hero product simulation**.
